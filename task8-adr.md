# ADR-002: Выявление и устранение «горячих» шардов

**Статус:** Принято  
**Дата:** 2025-07-29  
**Участники:** Архитектурный комитет «Мобильный мир»  

---

### Набор метрик для отслеживания состояния шардов

1. **Количество запросов к шардам:**
  - отслеживать количество запросов к каждому шарду за определённый период времени;
  - выявлять шарды с аномально высоким количеством запросов.

2. **Время отклика шардов:**
  - измерять время отклика каждого шарда на запросы;
  - определять шарды с увеличенным временем отклика, что может указывать на перегрузку.

3. **Объём данных на шардах:**
  - контролировать объём данных, хранящихся на каждом шарде;
  - предотвращать ситуации, когда один шард содержит значительно больше данных, чем другие.

4. **Использование ресурсов (CPU, память, дисковое пространство):**
  - мониторить использование CPU, памяти и дискового пространства на каждом шарде;
  - выявлять шарды, которые потребляют больше ресурсов, чем остальные.

5. **Соотношение операций чтения и записи:**
  - анализировать соотношение операций чтения и записи на каждом шарде;
  - отслеживать шарды с дисбалансом между операциями чтения и записи.

6. **Распределение данных по категориям/геозонам/пользователям:**
  - проверять распределение данных в соответствии с выбранной стратегией шардирования;
  - выявлять категории, геозоны или пользователи, создающие непропорциональную нагрузку.

### Механизмы автоматического перераспределения данных

1. **Использование встроенных механизмов MongoDB:**
  - MongoDB предоставляет инструменты для управления шардированием и балансировкой данных;
  - можно использовать команды и настройки для перераспределения данных между шардами.

  Примеры команд:
  - проверка статуса шардирования: `db.runCommand({ shardStatus: 1 })`;
  - добавление нового шарда: `sh.addShard("<connection string>")`;
  - разделение чанка: `sh.splitAt(<collection>, <split key>)`;
  - перемещение чанка на другой шард: `sh.moveChunk(<collection>, <destination shard>, { force: true })`.

2. **Разработка скриптов для мониторинга и перераспределения данных:**
  - создать скрипты, которые будут регулярно отслеживать метрики состояния шардов;
  - при обнаружении дисбаланса инициировать перераспределение данных с помощью команд MongoDB;
  - настроить расписание выполнения скриптов (например, раз в час или раз в день).

3. **Использование сторонних инструментов для мониторинга:**
  - внедрить системы мониторинга (например, Prometheus, Grafana), которые будут собирать и визуализировать метрики состояния шардов;
  - настроить алерты для оперативного реагирования на перегрузки шардов;
  - интегрировать системы мониторинга с скриптами для автоматического перераспределения данных.

4. **Пересмотр стратегии шардирования:**
  - периодически анализировать распределение данных и нагрузку на шарды;
  - при необходимости пересматривать стратегию шардирования (например, использовать составные ключи или изменить критерии разделения данных);
  - учитывать изменения в поведении пользователей и популярности категорий товаров.
